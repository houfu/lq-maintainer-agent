# What the session logs showed, and what v0.8 does about it (PROPOSED 2026-11-09)

Field request from the maintainer, in their words, after lq-ai shipped
v0.9.1:

> For this version, I want you to read the sessions and identify pain
> points you can fix. For example, the gate that blocks code
> development is painful for a maintainer who may want to be a coder
> on the repo too.

Two read-only analyses were run over the maintainer's own machine on
2026-11-09: every Codex session (1,264 rollout files, 97 of them
sessions where the plugin was active, 68 with a skill invoked, 23
August to 9 November) and every Claude Code session in the lq-ai
checkouts (82 main and 194 subagent files, 11 plugin runs, 26 August to
9 November). The three reports, with a pointer for every claim, are held by the
maintainer outside the repository: they quote private session logs,
and whether a redacted copy joins `docs/research/` is the maintainer's
call. Their file names are `pain-codex.md`, `pain-claude.md` and
`blocker-calibration.md`; the v0.8.0 release notes say where they are
kept.
Counts from keyword filters are lower bounds. The maintainer's own
words are quoted; contributors are referred to by PR number.

## What worked, and should not be touched

Findings carried `file:line` and pinned canon permalinks (PR 599's
sixteen majors each cite an auditor-design section; PR 775's two
findings were fixed in the author's next commit with regressions; PR
783's blocker failed the regression against the original code). The
agent almost never retried a blocked command (2 same-class retries in
114 Codex blocks) and produced a copy-paste hand-over 50 times. Cached
results were re-verified before being shown (PR 403 resume, PR 663
re-review against a moved `main`). Coverage statements were honest
("static review; no contributed code was executed"). PR 669 went from
review to merge in three hand commands with an aligned decision.

## Two things the record says about how the agent is used

- **Codex is the main host now** (105 of 158 receipts, nearly all since
  October, on `gpt-6.1-sol`), and every Codex session runs with
  `writes=hand-over` by construction. The gated comment flow has been
  used once on Codex, as a test. Every public comment, label and close
  in the record was pasted or run by the maintainer. The coder floor
  does not change this for review sessions — RT-04 stands — but it
  removes the same ceremony from the maintainer's own development work,
  which is where most of the relay turns were.
- **The maintainer reviews their own PRs with the tool** (PRs 599, 631,
  663, 669), at full density: 44 findings on 599, a four-pass team on
  631. The maintainer accepted most of them. The same density on an
  external contributor's PR would be a fairness problem, and no
  external PR in the window received it; the confidence readings are
  what makes that difference auditable rather than incidental.

## Deferred, with a reason each

- **`.maintainer/` folders diverging between worktrees and the base
  checkout** (30 hand copies). The convention lives in lq-ai's
  checkouts; the plugin writes to the canary's `data=` path. Suggestion
  for the maintainer: point `CLAUDE_PLUGIN_DATA` at one absolute path
  in the base checkout, or symlink the worktrees' `.maintainer/` to it.
- **Codex read-only agents.** Ship the install step in onboarding and
  verify it from the canary (an `agents=` field). One release later.
- **A batch skill.** Needs its own proposal: what a batch asks the
  maintainer once, and what it never asks.
- **Mid-session feedback capture.** A rule that appends to the feedback
  log when the maintainer corrects a call in-session, not only at
  finalize.
- **Pushing to a contributor's branch from a review session.** The
  maintainer asked for it fifteen times on Codex. It stays blocked on
  the review floor: a review never writes code into the item it is
  judging. The coder floor exists so the maintainer can do it in a
  session that is not a review.

## Honest status

- Every "Fixed" row is a rules, template or hook change in this
  release with tests where a test is possible (hook: 459 checks; rules
  index; golden lint). None has run against a live PR yet; the first
  review on each host after v0.8.0 installs is where they are proved.
- The counts come from two independent reads of two different log
  formats and are not reconciled item by item; where they disagree the
  report with the pointer wins.
- The hook change re-arms Codex's trust hash. The first Codex session
  after updating must re-trust the hook in `/hooks` before any skill
  will run.
